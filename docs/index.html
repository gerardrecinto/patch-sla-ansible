Four small tools that fit together.

Patch carefully, check the real hardware, and keep evidence a reviewer can read.

SLA checker

Reads detected and patched times per finding. Reports ok, late, open, or breached against 48 hours for critical. Exits 1 on a breach.

patchsla/sla.py

Patch role

Security updates one host at a time, stops on the first failure, skips any host with a run in progress, reboots only when allowed.

ansible/roles/patch

Real-time check

Asserts a PREEMPT_RT kernel, isolated CPUs, and the realtime tuned profile. Also a plain Bash version.

roles/rt_check, scripts/rt-check.sh

Proxmox VM playbook

Clones a VM from a template on a Proxmox VE cluster with the community.proxmox collection.

playbooks/proxmox_vm.yml

Container and CI

A Containerfile that works with Docker, Podman and Buildah, and a Jenkinsfile that runs tests, syntax checks and the SLA report.

Containerfile, Jenkinsfile

NIST mapping

Which control each output is evidence for: SI-2, CM-2, CM-3, CM-6, AU-12. A mapping, not a compliance claim.

docs/NIST_MAPPING.md

Run it from a clean checkout.

Python 3 and pytest are enough to try the checker. Ansible is only needed for the playbooks.

git clone https://github.com/gerardrecinto/patch-sla-ansible
cd patch-sla-ansible
python -m pytest -q tests
python -m patchsla.sla tests/findings.json

What is real, and what is not verified.

Every claim on this page comes from a command that ran. Anything that did not run is listed on the right.

Verified

  • 5 pytest tests pass. The sample report exits 1 on the breached finding.
  • All three playbooks pass ansible-playbook --syntax-check.
  • shellcheck is clean on the real-time check script.

Not verified

  • Nothing ran against real hosts, a Proxmox cluster, or a real-time kernel.
  • The reboot path and needs-restarting handling are untested.
  • The Containerfile and Jenkinsfile were not run.

Questions before you try it.

Why skip a host instead of patching it later?

A flag file marks a host as mid-run. The role skips it and the SLA report keeps counting, so a skipped critical shows up as open and then breached. The delay is visible instead of silent.

Is this a compliance tool?

No. docs/NIST_MAPPING.md says which control each output supports as evidence. It does not claim an ATO or any audit result.

Why 48 hours?

It is the default for critical findings and is one dictionary in patchsla/sla.py. Change it there.
